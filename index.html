00业务底座 / 第 1–2 周先看懂业务，再定义问题业务建模 · 数据口径 · 价值判断20–30 小时＋

阶段目标 把“提前发现缺料”变成可计算、可验收的业务问题。

学什么 · 按这个范围学习

  • 画出需求 → 采购申请 → 采购订单 → 供应商承诺 → 收货质检 → 可用库存的单据流。
  • 理解物料、供应商、工厂/仓库、计量单位、BOM、采购提前期、最小起订量与安全库存。
  • 区分现存量、可用量、锁定量、在途量；区分计划到货、承诺到货和实际到货。
  • 定义谁处理预警、何时升级、什么算关闭；记录目前人工统计时间与漏报案例。

这次要交付项目 V0：画一张缺料处理流程图，写一页需求说明和数据字典。用模拟的 20 个物料，手工算出未来 14 天的缺料清单。

过关标准 · 做到后再向前

常见误区“在途总量足够”不代表不会缺料：到货晚于需求日期仍会缺料。

现在可以不学：暂不学习完整 ERP 源码、复杂多级 MRP 或全公司业务架构。

02数据能力 / 第 9–14 周让数据和缺料计算可信SQL · 数据建模 · pandas · 时间口径60–90 小时＋

阶段目标 从表格分析升级到可追溯、可重复运行的数据服务。

学什么 · 按这个范围学习

04AI 应用 / 第 25–30 周把大模型接入真实业务模型 API · 结构化输出 · 文本提取 · 评估60–90 小时＋

阶段目标 把供应商的自然语言回复转成有证据、可复核的交期建议。

学什么 · 按这个范围学习

  • 理解 Token、上下文窗口、推理延迟、费用、幻觉和输出不确定性；掌握基础模型选型。
  • 调用模型 API，配置密钥、超时、限流、重试；用结构化字段约束输出并再次校验。
  • 提取物料、订单行、数量、日期、承诺状态与原文证据；遇到“争取、预计、下周”保留不确定性。
  • 区分提示词设计与上下文组织：提供当前订单、沟通时间、历史承诺和业务规则。
  • 建立固定样本集，对比提示词与模型版本；统计字段准确率、无法判断比例、延迟与单次成本。

这次要交付项目 V4：交期回复解析助手。粘贴供应商邮件或消息，生成交期候选记录，由采购员确认后入库。

06Agent 工程 / 第 37–44 周让 Agent 稳定地完成任务工具调用 · 工作流 · 状态 · 人工审批80–120 小时＋

阶段目标 形成“查询 → 分析 → 建议 → 审核 → 执行 → 留痕”的业务闭环。

学什么 · 按这个范围学习

  • 先用普通 Python 实现一次工具调用，再学习状态、节点、分支、停止条件和检查点。
  • 使用 LangGraph 构建显式流程，区分固定工作流与由模型动态选择工具的 Agent。
  • 工具契约包含输入校验、用户身份、数据范围、错误类型；敏感操作在服务端重新校验。

03 / BUILD ONE REAL SYSTEM

贯穿整条路线的项目蓝图

项目名：缺料与供应商交期协同工作台。首期服务一个工厂或采购小组，围绕一条预警的完整生命周期迭代。

业务闭环 / 让风险最终有人处理

先把“缺料”计算口径说清楚

预计结余 PAB(t)
= PAB(t−1) + 当日可用到货 − 当日需求

PAB(0) 为纳入本模型的期初可用库存。先明确锁定库存与已分配需求的处理，避免同一项重复扣减。每日到货只计本规则认可、能投入使用的数量。

  • PAB(t) < 0：实际供需缺口；PAB(t) 低于安全库存：缓冲不足，两类预警分开。
  • 到货日期按可用日期计算，必要时加上运输、收货和质检时间。
  • 需求是否已包含逾期未满足量必须固定口径；累计负结余不能每天再重复加成新缺口。
  • 多级 BOM、替代料、损耗率、批次与跨仓调拨，是首期之后的扩展。

一个可以手工验证的例子

期初可用库存 50；供应商承诺第 3 天到货 40，假设当天即可使用。

日期需求到货预计结余
第 1 天30020
第 2 天350−15
第 3 天104015

判断：即使总到货足够，第 2 天仍有 15 的缺口。第 3 天的恢复不能抹去前一天的断供风险。这个例子假设未满足需求继续保留；若存在取消或损失销售，模型需要另行处理。

AI 的作用：提取“40 件第 3 天可到”的证据，解释风险，生成催交建议。数量和日期的供需计算由程序完成。

系统架构 / 技术随阶段逐步加入

起步只需要脚本和文件，随后加数据库与网页。RAG、LangGraph、向量索引和观测平台按需求加入，不必第一天部署整张图。LLM 不直接持有任意写库权限。

最小数据模型

物料、供应商、工厂/仓库、库存快照、需求行、采购订单行、交付计划行、承诺历史、收货记录、预警、处置任务。

每条预警都能解释

展示物料、缺口数量、首次缺料日、相关需求、到货依据、数据更新时间、负责人和当前处置状态。

准时交付率先定分母

按行、批次或数量统计须明确；原始承诺与最新承诺分开保存。避免通过反复改交期“改善”准交率。

07 / A SMALL GLOSSARY

第一次遇到这些词，看这里

API

系统之间约定好的调用接口。网页查缺料、Agent 查订单，都通过接口获取数据。

前端 / 后端

前端是用户操作的页面；后端负责规则、权限、接口和数据处理。数据库保存业务事实。

ETL / 数据管道

把源系统数据取出、清洗、转换并写入目标系统的过程。还必须能对账和追踪失败。

LLM / 大语言模型

理解和生成语言的模型，适合文本提取、解释、草稿与工具选择；输出仍需验证。

RAG

先检索相关资料，再让模型依据资料回答。检索正确和回答有依据是两件需要分别评估的事。

Embedding / 向量

把文本表示为可比较的数字，用来找语义相近的内容，不替代 SQL 的精确计算。

工具调用

模型提出调用某个函数及其参数，由程序校验并执行；模型本身不应直接拥有全部系统权限。

Agent / 工作流

Agent 可由模型决定下一步；工作流明确规定步骤与分支。实际系统经常把两者结合。

MCP

连接 AI 应用与工具、数据的一种协议。学它之前先理解 API、工具契约和权限。

幂等 / 可恢复

同一动作重试不重复产生结果；中途失败能从明确状态继续，尤其适合创建任务和发送通知。

MRP / BOM

MRP 按需求、库存和提前期推算物料需求；BOM 描述产品与组件的用量关系。

ERP / WMS / MES / APS

分别偏向企业资源、仓储、制造执行与高级计划排程；落地时需要明确各系统的数据权威和接口。
